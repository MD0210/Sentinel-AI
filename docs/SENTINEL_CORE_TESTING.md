# Sentinel Core: local model setup and test guide

This guide covers the first Core milestone: route an authorized user request through a configurable model provider. It does not enable tool execution, repository writes, agent delegation, or deployment.

## 1. Run the automated test suite

From the repository root with Python 3.10+ installed:

```bash
python -m pip install -r requirements-test.txt
python -m compileall -q agent security voice scripts tests main.py
python -m unittest discover -s tests -p "test_*.py" -v
```

The model-provider and model-router tests use mocked providers and HTTP responses. No API key, model download, microphone, or running model is required.

## 2. Run Sentinel with a local Ollama model

1. Install and start Ollama from https://ollama.com/.
2. In a terminal, download a model, for example:

   ```bash
   ollama pull llama3.2
   ```

3. Set configuration before starting Sentinel.

   **Windows PowerShell**
   ```powershell
   $env:SENTINEL_MODEL_PROVIDER = "ollama"
   $env:SENTINEL_MODEL_NAME = "llama3.2"
   $env:SENTINEL_MODEL_BASE_URL = "http://127.0.0.1:11434"
   $env:SENTINEL_MODEL_TIMEOUT = "60"
   python main.py
   ```

   **macOS/Linux**
   ```bash
   export SENTINEL_MODEL_PROVIDER=ollama
   export SENTINEL_MODEL_NAME=llama3.2
   export SENTINEL_MODEL_BASE_URL=http://127.0.0.1:11434
   export SENTINEL_MODEL_TIMEOUT=60
   python main.py
   ```

4. Complete Sentinel's existing wake phrase and authentication flow, then enter a request such as `Explain what a Python class is in two sentences.`
5. Confirm the response is generated by the configured model rather than the old "I received your request" echo.
6. Stop Ollama and submit another request. Sentinel should display a normalized model-unavailable message rather than a traceback or raw provider error.

## 3. Free hosted option: Google Gemini API

Gemini offers a free API tier for eligible models, subject to quota and availability limits; it is not unlimited. Google's current pricing page lists free-tier model access, but limits and model names can change. Check the [official Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) before choosing a model. Free-tier data may be used to improve Google's products, so do not send secrets or sensitive data.

1. Create or view an API key in [Google AI Studio](https://aistudio.google.com/apikey).
2. Set the following environment variables before launching Sentinel.

   **Windows PowerShell**
   ```powershell
   $env:SENTINEL_MODEL_PROVIDER = "openai-compatible"
   $env:SENTINEL_MODEL_NAME = "gemini-3.8-flash"
   $env:SENTINEL_MODEL_BASE_URL = "https://generativelanguage.googleapis.com/v1beta/openai"
   $env:SENTINEL_MODEL_API_KEY = "YOUR_GEMINI_API_KEY"
   $env:SENTINEL_MODEL_TIMEOUT = "60"
   python main.py
   ```

   **macOS/Linux**
   ```bash
   export SENTINEL_MODEL_PROVIDER=openai-compatible
   export SENTINEL_MODEL_NAME=gemini-3.8-flash
   export SENTINEL_MODEL_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
   export SENTINEL_MODEL_API_KEY='YOUR_GEMINI_API_KEY'
   export SENTINEL_MODEL_TIMEOUT=60
   python main.py
   ```

   Replace the example model with one currently available to your API key if needed. Never commit the key to GitHub or put it in source code. Use a local environment variable only for this manual test, and clear it when finished. See Google's [OpenAI compatibility guide](https://ai.google.dev/gemini-api/docs/openai) for the endpoint format.

## 4. Other compatible hosted providers

The same adapter works with an OpenAI-compatible chat-completions endpoint: set `SENTINEL_MODEL_PROVIDER=openai-compatible`, `SENTINEL_MODEL_NAME` to a model supported by the service, `SENTINEL_MODEL_BASE_URL` to its API base URL, and `SENTINEL_MODEL_API_KEY` to its key. The default base URL is `https://api.openai.com/v1`, but usage there may be paid. Hugging Face Inference Providers has a small monthly free credit for free users, subject to change; check its [pricing page](https://huggingface.co/docs/inference-providers/pricing). Do not assume a hosted endpoint is free or unlimited.

## 5. Configure model routing

Sentinel classifies each prompt using transparent keyword rules. Coding cues take precedence over reasoning cues; unmatched requests are classified as general. If a specialist model is not configured, Sentinel automatically uses the default model. Classification does not make an additional model/API call.

The existing `SENTINEL_MODEL_*` variables configure the default model. Optional specialist routes require both a provider and a model name.

**Example: keep general and reasoning on the default model, route coding requests to a separate local model (PowerShell):**

```powershell
$env:SENTINEL_MODEL_PROVIDER = "ollama"
$env:SENTINEL_MODEL_NAME = "llama3.2"
$env:SENTINEL_MODEL_CODING_PROVIDER = "ollama"
$env:SENTINEL_MODEL_CODING_NAME = "qwen2.5-coder:3b"
python main.py
```

Pull the specialist model first if needed:

```bash
ollama pull qwen2.5-coder:3b
```

Specialist configuration variables:

| Route | Required variables | Optional variables |
|---|---|---|
| Coding | `SENTINEL_MODEL_CODING_PROVIDER`, `SENTINEL_MODEL_CODING_NAME` | `SENTINEL_MODEL_CODING_BASE_URL`, `SENTINEL_MODEL_CODING_API_KEY`, `SENTINEL_MODEL_CODING_TIMEOUT` |
| Reasoning | `SENTINEL_MODEL_REASONING_PROVIDER`, `SENTINEL_MODEL_REASONING_NAME` | `SENTINEL_MODEL_REASONING_BASE_URL`, `SENTINEL_MODEL_REASONING_API_KEY`, `SENTINEL_MODEL_REASONING_TIMEOUT` |

For hosted specialists, set the route-specific base URL and API key too. Never commit keys. An unconfigured specialist route falls back to the default model. The initial classifier is intentionally simple; review and improve its routing rules as real usage reveals misclassifications.

## Current limitations

- The Core performs one synchronous text-generation call per request.
- The first turn sends the current request only; conversational history is not yet persisted.
- Routing is rule-based, not semantic; complex or ambiguous prompts can be classified incorrectly.
- Ollama must be installed and its model pulled separately.
- The hosted adapter supports OpenAI-compatible chat-completions APIs, not every provider-specific API.
- Authentication behavior is inherited from the existing application and is not being reworked in this workstream.
- No tools or agents are called by model output. This is intentionally a text-only model loop.
